# Build log: Player Two Growth House

Started 19 Oct 2026, after the user said "build" on the approved spec.
One line per assumption or decision made during the build. Each is a default the client can accept or change.
INTERNAL: never ship this file to the client's site.

## Stack and tooling

- A01: Next.js **16.4.2** (App Router, scaffold defaults `cacheComponents` + `partialPrefetching` kept), React 19.3, Tailwind 4.3, TypeScript, Node >=22. Scaffolded with create-next-app 16.4.2.
- A02: `@types/node` raised from ^20 to ^22 to match the installed Node 22 and vitest 5's peer range.
- A03: `npm audit` reports 5 high-severity findings, all in ESLint dev tooling (`eslint-config-next` → `@next/eslint-plugin-next` → `fast-glob` → `micromatch` → `braces`, a pattern-matching DoS). Dev-only, never shipped to the site. Not force-fixed, because the fix is a breaking downgrade.
- A04: Tests use vitest 5.0.5. Formula and validation tests in `lib/leakReport.test.ts`.
- A05: The impeccable design skills (`typeset`, `layout`, `polish` …) are installable skills, not CLI commands, and installing them would modify the user's Claude config. Not installed without asking. `npx impeccable detect` (CLI) is used for checks instead.

## Tokens

- A06: Token layer generated by `scripts/tokens.mjs` (`npm run tokens`, also runs before `dev` and `build`). Colours, radii and spacing come from `@google/design.md@0.4.0 export --format css-tailwind`. Typography is read from DESIGN.md front matter directly, because every v0.4.0 export format drops unitless `lineHeight`. Worth reporting upstream.
- A07: Tailwind's default colours, radii, font families and breakpoints are switched off (`--*: initial`), so only DESIGN.md values exist as utilities.
- A08: `--font-weight-*` theme keys are removed from the export, because they collide with font-family utilities of the same names. Weights live inside the generated `type-*` utilities instead.
- A09: Phone scaling for headlines uses DESIGN.md's factors (display ×0.6, lg ×0.7, md ×0.8, sm/title ×0.9) as `clamp()` between 390px and 1280px viewports. **hud-score ×0.75 on phones is our assumption** (DESIGN.md doesn't give one).
- A10: Sticker shadows, the press state, breakpoints and pixel-stepped corners are defined in `app/globals.css` from token variables only, so no new values exist.
- A11: `lib/tokens.json` (generated) holds the colour hex values for email HTML, where CSS variables don't work.

## Fonts

- A12: Chunk (Matsero, commercial, licence unconfirmed) is **not committed**. `public/fonts/chunk/` is git-ignored. `@font-face` points at `/fonts/chunk/Chunk.woff2`; without the file, DESIGN.md's fallback stack renders and the request 404s. Deployed builds will show the fallback until the licence is confirmed and the file is added.
- A13: Source Sans 3 (400/600/700) and IBM Plex Mono (500/600) are self-hosted through `@fontsource` (OFL-1.1), not `next/font/google`, so the family names match DESIGN.md tokens exactly. Trade-off: no automatic preload or size-adjust fallback.

- A15: US English spelling, since the market is the US ("enrollment", "inquiries"). The spec draft said "enrolment"; changed to US spelling.
- A16: The hero headline uses the brand audit's recommended line "You're not short on leads. You're leaking the ones you already paid for." The audit recommends A/B testing it against a direct-outcome headline later.
- A17: Hero HUD tag "Insert coin · Unlock growth" is from the client's tagline. The closing HUD "Press start for Player Two" is 5 words, one over DESIGN.md's ~4-word HUD guide; kept because it's the client's own line.

Debug Mode is noted "On its own, or as the first step" (public copy). Cheat Codes is noted "Built after we diagnose". - A19: Leak cards: 4 symptoms written from the doc's public lines. "Happy customers often don't think to leave a review unless someone asks" is a general statement, not a statistic.
- A20: FAQ: 6 questions. Answers come from public-section statements. "How much does it cost?" is a **visible placeholder** pending David (D3).
- A21: "Who we are" uses the doc's Player 1 / Player 2 copy plus "a small, hands-on team" (from the doc's positioning). Team names, photos and team size are a **visible placeholder** (C7).
- A22: Footer copyright reads "© Player Two Growth House" with no year (avoids a stale year) and no legal entity name (unknown).
- A23: The 404 page uses a light game line ("Game over? Not quite.") plus plain words.
- A24: Header on phones (<640px) shows the wordmark, a compact **"Book a call"** button and an icon-only menu button. The full "Book a free Recon Call" label can't fit at 390px beside the 140px minimum-width wordmark. Desktop keeps the full label.
- A25: The four header links are hidden below 1024px and live in the menu. The menu closes on link tap and on Escape.

## Components and behaviour

- A26: Size tokens added to DESIGN.md during the build (control-lg/md, header/header-sm, level-node, icon, cartridge-stripe, track, wordmark-min, badge-lg/sm), so no component needs a raw size. DESIGN.md re-linted clean.
- A27: Sticker edge is context-aware: ink outline and shadow on light surfaces; **cream outline and forest shadow on dark bands** (an ink shadow is invisible on ink). Cream panels inside dark bands (`.on-light`) switch back to ink. Not specified in DESIGN.md. It's our reading of "sticker" on dark.
- A28: Focus ring: ink on light, spark on dark, ink again inside cream panels on dark bands (spark on cream fails at 1.34:1).
- A29: Pixel icons (phone, quote, star, mail, lock, unlock, next) are **draft 8×8 art drawn during the build**. The phone icon reads weakest. Designer replacement is welcome (C8).
- A30: HUD tags appear only on the hero ("Insert coin · Unlock growth"), the Leak Report ("Level 1 · Leak Report") and the closing ("Press start for Player Two"). They were removed from 6 other section headings after `impeccable detect` flagged the "small label above heading" pattern 8 times; the market scan had named the same pattern as a template cliché (Fire Fuel).
- A31: On desktop the Leak Report result column is sticky beside the form, so the score screen stays in view while filling in.
- A32: Leak Report inputs are text fields with `inputMode="numeric"` (not `type=number`), so our own validation messages apply. The money field accepts "$" and commas.
- A33: The result updates only when "Show my Leak Report" is pressed (spec). The emailed report always uses the inputs that produced the on-screen result.
- A34: The big monthly figure counts up visually (aria-hidden). Screen readers get one polite announcement of the final figures, not every intermediate value.
- A35: Childcare wording: "enrollment", "tours or inquiries", "first month's fee" (C11 draft). The cold-quote row reads "Cold tours or inquiries" for childcare. Awkward, flagged for the copy review.
- A36: Email form: the email is required; first name and business are optional. Consent is a line of text under the button, not a checkbox (spec). The honeypot field is named `website`. Submissions under 3 seconds after the result appeared are treated as bots (silent success, nothing sent).
- A37: **No rate limiting** on `/api/leak-report`: there's no store to count requests in. Only the honeypot and timing check apply. If abuse appears, add Vercel's firewall rules or a KV-backed limiter.
- A38: Emails go through the Resend REST API with `fetch` (no SDK dependency). The team copy is sent first, with reply-to set to the owner; then the owner's report, with reply-to set to the team inbox. Success only if both send. If the owner send fails after the team send, a retry duplicates the team copy, which we accept.
- A39: The team email tells the reader to add the lead to the CRM, since leads don't reach GoHighLevel automatically.
- A40: Booking: Calendly uses its documented popup widget (`Calendly.initPopupWidget`). **The Cal.com path (`Cal("modal", { calLink })` plus the embed bootstrap) is unverified** until a real Cal.com link exists. Every booking button is a real link that opens the booking page in a new tab if the script isn't loaded, is blocked, or the user middle/cmd-clicks.
- A41: Provider detection: `NEXT_PUBLIC_BOOKING_PROVIDER=cal`, or any `cal.com` URL, means Cal.com. Anything else means Calendly.
- A42: The booking script loads lazily (after the page is idle), and only when a booking URL is set.
